# Access Management audit — 18 September 2026

Version: `20.0.1.0.8`. Environment: local Odoo 20 Enterprise, PostgreSQL on
port 5433. Regression fixtures ran on a copy of `v20_ent` and a separate clean
installation, with background cron disabled. Live business records were not
used as destructive test fixtures.

## Issues corrected

| Area | Correction |
| --- | --- |
| Apps visibility | Upgrade repairs missing module classification so the installed app matches Odoo 20's standard Apps filter. |
| Global Read-Only | UI restrictions now consistently cover import, export, archive, delete and property creation. Both profile and user read-only settings block module changes. Business CRUD enforcement is verified through actual operations and permission checks. |
| Conditional fields | Fields used by conditions are loaded invisibly; related embedded views use their own model's rules. Record conditions no longer reach the search bar, which has no current record. |
| Browser view cache | View architectures use in-page caching instead of persistent disk caching, so refreshing after a profile change loads current restrictions and restores removed controls. |
| Role grants | New assignments track groups they actually add, preserve pre-existing manual groups, and retain shared groups until their last role grant ends. Archived nested roles stop granting through their subtree. Reassignment reconciles both users. |
| Access requests | Submitted targets and dates are protected. Future profile grants respect their start date. Revocation tracks the assignment actually granted, preserves earlier manual membership and overlapping valid profile requests, and avoids deleting a replacement role assignment. Approved requests must be revoked before deletion. Duplicate role requests produce a clear error. |
| Export | Related-model and translated field paths cannot bypass field exclusion, masking or model export restrictions. |
| Audit trail | Bulk profile changes use each record's own previous users and active state. |
| Schedules | Daily rule windows spanning midnight are accepted and tested. |

## Operational details and limits

Save profile changes and refresh already open user sessions to update all browser
controls. Normal Odoo administrator/superuser privileges and technical records
needed for the web client retain their existing semantics.

Request activation/expiration and dated role group reconciliation run through
scheduled jobs. The default daily request schedule takes effect on the next job
execution. Record-dependent field conditions do not control the search bar;
configure search restrictions separately.

Old role/request records do not contain historical grant ownership. Migration
retains their previous revocation semantics and establishes tracking for future
changes. This live database had no existing roles or access requests to migrate.

AI provider transports and result application were tested using mocked provider
responses. Email workflow calls were mocked. Actual external AI services and
email delivery were not exercised. Passing these checks establishes the tested
behavior; it does not exhaust every third-party addon or future configuration.
